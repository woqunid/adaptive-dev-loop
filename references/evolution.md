# 自我进化 (Self-Evolution)

> 内嵌于 adaptive-dev-loop 的**步骤 9**。设计原则：条件触发、只改本 skill、独立视角评估、改动经用户批准、改后自检、失败回滚。目的是让 skill 从真实使用中纠偏、完善、优化自己。

## 何时触发（明显不顺才跑）

默认**不执行**。只有本次运行命中以下任一"明显不顺"信号才进入步骤 9：

- 自适应循环回流 ≥ 2 轮
- 任一确认门被用户否决或要求大改
- grilling 中需求理解被反复纠正（≥ 2 次）
- 触达迭代上限而升级
- 过程中用户明确表达对流程 / skill 的不满

未命中 → 跳过步骤 9，正常结束。**不要为进化而进化。**

## 进化作用域（只改这一份 skill）

只允许修改**本 skill 自身目录**下的文件：`SKILL.md`、`references/*.md`、`scripts/*`、模板。
绝不碰任何其他 skill、绝不碰用户的项目代码、绝不碰产物目录 `dev-loop/`。

## 保护区（禁止自我修改的核心不变量）

以下内容**永远不能**被自我进化改动或删除——它们是 skill 的骨架与安全护栏：

- **8 阶段闭环结构**（需求 → … → 审查 → 循环 → 交付）。
- **边界安全规则**：`boundaries.md` 的"绝不做"，尤其"不靠掩盖伪装通过""破坏性操作需确认"。
- **自我进化机制本身**：步骤 9、审批门、改前备份、改后自检、失败回滚。
- **description 的触发语义**（防止越改越不被触发）。

只允许进化：各阶段"怎么做"的措辞、grilling 问法、模板细节、checklist 条目、阶段内的解释与示例等**非结构、非安全**的部分。

任何触碰保护区的改进提议，**在产出阶段就过滤掉，不提交给用户**。`scripts/structure-check.sh` 会把这些不变量作为回归项强制校验——进化若破坏了保护区，自检必失败并触发回滚。

## 流程

### 1. 收集摩擦点
从产物目录（`iteration-log.md` / `requirement.md` / `analysis.md` + 对话）提取本次"流程摩擦点"清单：哪一步、什么现象、命中哪个触发信号。

### 2. 独立 critic 评估（防自夸 + 防过拟合）
用独立、对抗性的视角逐条审视——**优先用子 agent 扮演 critic**；无子 agent 的环境（如 Codex）则**显式声明"切换到 critic 对抗视角"再自审**。每条判断：
- **偶发 vs 系统性**：只有"换个需求也会重犯"的系统性问题才值得改；一次性的偶发问题丢弃。
- **改法**：优先"解释 why"，而非新增硬性 MUST；避免把单次特例固化成通用铁律（过拟合）。

### 3. 产出改进提议
对保留下来的系统性问题，每条产出：目标文件、具体 diff、理由、过拟合风险自评、是否触碰保护区。**触碰保护区的直接丢弃。**

### 4. 审批门（必须，对应用户"改前先问"的要求）
把所有提议以 diff 形式 + 理由 + 风险展示给用户，**逐条请用户批准**。用户否决的丢弃。无提议或全部否决 → 结束，不改。

### 5. 应用 + 自检 + 回滚
对每条获批改动：
1. **备份**：把当前 skill 整体复制到 `_evolution/backups/<时间戳>/`。
2. **应用**改动。
3. **自检**：运行 `scripts/structure-check.sh`（结构 + 保护区不变量回归测试）。
4. 自检**通过** → 追加 `_evolution/CHANGELOG.md`。
5. 自检**失败** → 从备份**自动回滚**，向用户报告"本次进化未通过自检，已回滚"，并附失败原因。

## CHANGELOG 格式

每次成功进化向 `_evolution/CHANGELOG.md` 追加一条：
```
## <时间戳>
- 触发信号：<命中了哪个>
- 文件：<改了哪个>
- 改动：<改了什么>
- 原因：<为什么，对应哪个系统性问题>
```
